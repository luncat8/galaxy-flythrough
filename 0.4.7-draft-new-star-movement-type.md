# 0.4.7 — Apocenter-guided orbital movement

## Goal

Add an opt-in third star-motion engine that maintains large-scale arms and bars
through stellar orbital dwell time, rather than relying only on the classic
closed-form wobble or the simple friction-field slowdown. Keep the existing two
engines unchanged. The new engine is a visual, deterministic orbital model, not an
N-body or self-gravity simulation.

The movement remains centred on the galaxy's actual `model.centre`. No galaxy-wide
rotation about an arbitrary world origin or infinite axis is introduced. Each star
moves in a focus-centred orbital plane derived from its birth vector, as in the
current 3-D orbit geometry.

## Hypothesis and falsifiable behavior

Stars spend more orbital time near apocenter than pericenter. If a star's apocenter
is placed on an existing high-density feature (spiral arm or bar) and that apsidal
line rotates with the galaxy's pattern speed, the moving population should maintain
those features without a force field. This is a visual stability hypothesis; it is
not claimed to be a self-consistent gravitational solution.

Acceptance checks:

- At `T = 0`, positions are exactly the stored birth positions.
- For eccentric orbits, angular speed is lower near apocenter than near pericenter.
- A spiral-disc apocenter points to the nearest spiral ridge; a bar-family
  apocenter points along the model's bar. These orientations rotate about the
  model centre at its effective pattern speed.
- The orbit is bounded and deterministic over long positive and negative time.
- CPU landmarks and the GPU star path use the same equations.
- The default `classic` engine and the existing `simple` engine retain their
  behavior and resource budget.

## Orbit construction

Add engine id `2`, named `apocenter`, selected from the existing Engine menu. The
star record remains 16 bytes and no per-frame compute state or allocation is added.
The new law is evaluated analytically in the existing star vertex shader and in a
CPU mirror for labels and picking.

For a birth position relative to the centre `q`, let `r = |q|` and `θ₀ = atan2(qᵧ,
qₓ)`. Select an apsis orientation `A₀` at the birth radius:

- Disc and pattern families in an armed spiral: choose the nearest of the `m`
  spiral ridges `armRidgeAzimuth(model, r) + 2πk/m`; an exact tie chooses the
  ridge with the greater unwrapped angle.
- Bar family: choose the nearer direction along the bar's major axis, using the
  spheroid's `tiltDeg`, with the same deterministic tie rule.
- Other cases: use the nearest radial direction to the star. This avoids
  artificially aligning a smooth spheroid or a featureless disc.

The existing amplitude-rank nibble sets bounded eccentricity `e = eMax · rank`,
with an engine default `eMax = 0.45` and a hard cap of `0.55`. The model's local
circular clock is `vFlat / max(r, rCore)` for disc galaxies and the existing
pressure clock for disc-less spheroids. Given true anomaly `f₀ = θ₀ − (A₀ + π)`,
compute the semi-major axis that puts the birth point exactly on the ellipse:

```
a = r · (1 + e cos(f₀)) / (1 − e²)
E₀ = atan2(√(1 − e²) sin(f₀), e + cos(f₀))
M₀ = E₀ − e sin(E₀)
M(T) = M₀ + (ωlocal − Ωp)T − phaseOffset
A(T) = A₀ + Ωp T + phaseOffset
```

Solve Kepler's equation `M = E − e sin(E)` with five bounded Newton iterations,
then derive true anomaly and radius:

```
ν = atan2(√(1 − e²) sin(E), cos(E) − e)
r(T) = a(1 − e cos(E))
p(T) = C + r(T) · (cos(A(T) + π + ν), sin(...), 0)
```

Use the existing deterministic per-star plane basis: `e0 = normalize(q)`, and
`e1` is its azimuthal tangent tilted by `orbitInclination(family, phase, rank)`.
The birth vector is `e0`; define the periapsis basis direction in that plane as
`eP = e0 cos(δ) + e1 sin(δ)`, with `δ = A₀ + π − θ₀`, and
`eQ = −e0 sin(δ) + e1 cos(δ)`. Rotate `δ` by `Ωp T + phaseOffset` and place the
star at `C + r(T) · (eP cos(ν) + eQ sin(ν))`. Thus every orbital plane passes
through the model centre and the 3-D orbit is not a rotation about one shared
world axis. At the exact centre, leave the star at the centre. `phaseOffset` is
the existing continuous pattern-rate rephase term: it is added to the apsidal
orientation and subtracted from relative mean anomaly, preserving each orbit's
phase when the Pattern Speed slider changes. With `e = 0`, this law reduces to the
local circular rate.

At `T = 0`, take an explicit identity path before evaluating the ellipse. This keeps
the current sampled density exact and avoids roundoff at the initial frame.

## Data flow and integration

- Extend `OrbitLib` with `ENGINE_APOCENTER`, engine name, and CPU mirror helper.
- Reuse the existing `CameraUniform.engine` lane: `(id, eccentricityMax,
  barTiltRadians, 0)`. No uniform-buffer growth.
- The shader reuses already packed orbit dynamics and spiral parameters to derive
  the local clock, pattern speed, phase offset, and arm ridge. No galaxy-specific
  constants are introduced in WGSL.
- The renderer selects the apocenter vertex function for engine id 2; only the
  simple engine continues to use the compute-integrated theta buffer.
- Label and selection projection call the CPU apocenter mirror when this engine is
  selected. No additional landmark accumulator is needed.
- Update menu text, URL parameter documentation, tests, and the 0.4.x worklog.

## Validation

Extend `experiments/orbit-test.js` with CPU invariants for identity, feature
alignment, rotation around non-origin centres, the slow-at-apocenter dwell property,
long-time boundedness, and pattern-slider phase continuity. Add f32 CPU/GPU replay
cases for the new law and a `wgsl-validate` structural contract for its shared
formula and engine dispatch. Run `python3 scripts/run.py all-tests` and
`python3 scripts/run.py wgsl-exec` where the optional dependency is installed.

## Limits

This is a visual orbital approximation. The specified apses are prescribed by the
existing arm/bar density features; the model does not solve collective gravity,
resonant trapping, or the self-consistency of a collisionless stellar system. Do
not silently make this the default engine: compare it visually against the existing
engines before considering that change.
