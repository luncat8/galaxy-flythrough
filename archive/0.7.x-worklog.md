# 0.7.x worklog — formation

The series is specified in [`formation-plan.md`](../formation-plan.md). This log
records what shipped against it.

## 0.7.0 — 2026-10-22 — The clock stops re-rolling what is on screen

Plan §6 R3, the smoothness contract's first rule and the one confirmed jump.

**Defect.** `renderer.refreshObjects` re-placed the whole composite block on an
epoch change (`generateObjects` → `placeObjects` against the *current* model,
every member re-seeded from the new list) whenever the age had moved
`OBJECT_REFRESH_AGE = 0.02` Gyr. Cluster and HII members are records in the same
`StarPacked` buffer as the field, so at the top star rate (99 Myr/s) that re-roll
replaced a slice of the visible sky about five times a second, and every nebula
billboard jumped with it. E4 had already removed this class of defect for the
field (draw once, place by the epoch map); the object block was left behind
because its *placement* reads age-dependent acceptance rates.

**Fix.** The block is drawn with the field and carried. `refreshObjects`,
`OBJECT_REFRESH_AGE` and `state.objectsEpochAge` are gone, `setEpoch` no longer
places anything, and `regenerate`/`rebuildPopulation` remain the only callers of
`generateObjects`. Nothing is lost by it: a member's look is epoch-independent by
construction — `deriveStarWithAge` imposes the object's own age, and the
metallicity follows the component — so the refresh was re-rolling seats to
recompute bytes that would have come back identical. The gas-driven change in the
*rate* of new objects returns in 0.7.4/0.7.5 as a gate on the running epoch, not
as a re-place.

**Validated.** `renderer-test` **135/135**, with the old "an epoch change re-places
the objects, rationed by age" pin replaced by its opposite: the object block's
record bytes and member count are identical before, during and after a walk to
0.5 → 0.6 Gyr → back to the reference. `view-tests` 16/16, `changed` 7/7
(`export-parity`, `m1-smoke`, `wgsl-validate`, `preset`, `renderer`, `hdr`,
`view-modes-page`), `node --check` and `git diff --check` clean. No browser
verdict is claimed; the row is V14 in `deferred-browser-visual-plan.md`.

## 0.7.1 — 2026-10-23 — A star appears when its gas became it

Plan §2–§3, F1–F3. The global procedural field now carries an `f32` birth
channel, the vertex gate and the look of each star follows its elapsed age.

**Plan review / corrections before landing.** The initial §2.1 proposal used
`hash01(fieldStarSeed * 31 + 5)`, which was not actually a new channel: 4 and 5
are already the evolution-state rolls. The shipped birth channel is 6, using the
same legacy channel convention (`hash01(seed * 31 + 6)`) and leaving every
existing roll alone. The first inverse-CDF-only trial also removed most of the
spatially gated arm-young population (OBs are a conditional arm/lane sub-sample,
not a generic draw from the broad thin-disc window). The birth law is therefore
a measured hybrid: accepted thin-disc arm/lane stars retain their existing
reference-epoch age draw as `AGE_REF − armAge`; all other stars use the
component-window inverse-CDF at the reference span. This preserves the ridge
without reviving the rejected `AGE_REF − sampleLocalAge` shortcut or its zero-age
pile. The implementation reuses the existing 1025-entry inverse table; it does
not add a second 40-iteration inverse per star. A second review correction
updated F4 before implementation: a hard `birth <= T` prefix cannot exactly
complement a `smoothstep`-faded visible census. F4 now integrates the same gate
from a 1024-bin histogram, normalized by its reference-epoch sum, with an
explicit 0.25 % error budget; the account/grid remain future work.

**Implementation.** `star-types.js` supplies the reference-span birth and the
arm/lane conditional. `star-sprites.js` writes the field's births to a separate
storage buffer at draw time; the 224-byte camera uniform carries epoch, fade
width and field count in its final vec4. The WGSL vertex stage returns fully
absent field stars off-clip and multiplies the fade into brightness. The CPU
mirror (`orbit.gateAt`) keeps fully absent stars out of pick, radius-scan, search
and selection-ring paths. Epoch look slices use `deriveStarWithAge(T − birth)`;
exposure calibration weights by the same smooth gate, so unborn stars do not
bias the field's brightness. Birth bytes are unchanged by an epoch walk and are
refreshed only for a new field/formation-law draw. Picked field-star planetary
inputs now use the same elapsed age as the visible star. The gate deliberately
covers the global procedural field block, not Gaia/landmarks, object members, or
the camera-resident local gap-fill; the latter needs its own carried birth data
and look sweep before claiming a completely empty hybrid frame.

**Validated.** `renderer` **138/138** (birth allocation/uniform, boundaries,
reference births held over an epoch, look sweep and exposure),
`star-types-evolution` checks include reference-window bounds and the arm
conditional, `orbit` **135/135**, `wgsl-validate` passes, and `wgsl-exec`
**122/122** executes the shipped shader's zero/half/full birth gate against the
CPU mirror. `planet-gen`, `search`, `star-select` and `m1-smoke` pass. The `changed`
suite passed **29/29**; after the final asynchronous-picker gate-age snapshot
refinement, `star-select` and `search` were re-run and passed. `git diff --check`
is clean. Running the WGSL check exposed a small `scripts/run.py` dispatch bug:
non-suite commands passed the whole argument list where the single command name
was expected; the wrapper now dispatches that name, so `wgsl-exec` works. No
browser/WebGPU visual verdict is claimed; V14 remains deferred.

## 0.7.2 — 2026-10-23 — Deep time: the galaxy starts at pure gas

Plan §7, F7. `AGE_MIN` lowered from 0.2 to 0, so the `Evolve` preset starts at
the galaxy's first light (135 AGE_STEPs instead of 133). Each degeneracy at
`T = 0` is resolved by meaning, not by a clamp:

**The heat floor.** `meanAgeAt(0) = 0`, so `pow(0/meanAgeRef, HEAT_EXP) = 0` and
`discHeightAt` collapses to zero scale height. The picker and label layer divide
by `H(R)` and the geometry becomes singular. Resolution: `HEAT_FLOOR = 1e-3`,
applied in `solveEpoch`. The birth gate hides every star regardless, so the
floor only keeps the *geometry* finite — no consumer reads it visually.

**The spheroid's absence.** `spheroidProgressAt(T=0) = 0`, `spheroidSize = 0`,
`spheroid.a/b/c = 0`. The existing `orbit.solveEpochParams` guard
(`epochBase.spheroidA > 0 && a > 0`) already prevents a division-by-zero in the
scale ratio; a 0-size spheroid maps nothing, and the bulge's stars are all
gated off by birth anyway. No new guard needed in orbit.js.

**The pattern speed.** `barPatternSpeed` previously computed
`omegaAt(dynamics, 0 * r0 * extent)` = `vFlat / rCore`, a large but non-zero
value. A 0-size spheroid means no bar has assembled — no pattern to drive.
Resolution: return 0 when `spheroid.a === 0`.

**The additive phase0.** `Math.log(0) = −∞`, which would poison the ridge's
phase anchor. Resolution: the existing guard `(size > 0)` covers it — when the
spheroid has not assembled, `delta = 0` and the stored base is kept verbatim.

**Arm contrast.** Already saturates at `ARM_CONTRAST_MAX` via the existing
`gasRatio` ceiling; at `T = 0` the gas-rich disc has maximum arm signal, which
is correct.

**Tests.** The evolution test bounds relaxed from `> 0` to `≥ 0` for
`spheroidProgress` and `spheroidSize` (the deep-time boundary). The pattern
speed test's reference formula now guards `spheroid.a > 0` to match the new
barPatternSpeed. The ridge and monotonicity checks skip `size = 0` (no bar has
assembled). A new section 9 validates every deep-time factor at `T = 0` across
all types: assembly = 0, gas = 1, spheroid axes = 0, heat floored, arm contrast
saturated, disc heights finite, barred omegaPattern = 0, phase0 unchanged.

**Validated.** `all-tests` **40/40**; `changed` **35/35** (galaxy.js reverse
dependencies); `wgsl-exec` **122/122**; `node --check` and `git diff --check`
clean. The `Evolve` preset now starts at 0.0 Gyr. No browser/WebGPU visual
verdict is claimed; V14 remains deferred.

## 0.7.3 — 2026-10-23 — The view gas is what the census shows

Plan §4, F4. The drawn census now drives the field's gas picture: a 1024-bin
birth histogram is built once per field draw, and `censusGasAt(age)` evaluates
the smoothstep presence sum at O(1024) per epoch step. The view gas replaces
the SFH `gasNow` only for the field's arm contrast; the SFH gas stays on
`populations` for every other consumer (nebulae, clusters, the gasRich gate).

**The histogram.** `writeFieldBirths` now calls `buildBirthHistogram` after
filling the birth staging array. The histogram covers `[0, spanRef]` in 1024
bins (a power of two, so the bin index is a shift). The reference-epoch
presence is precomputed once, so `formed(T) = presence(T) / presenceRef` is one
evaluation per frame, not two.

**The view gas.** `censusGasAt(age)` returns
`1 − (presence(age) / presenceRef) · (1 − gasFraction)`. Both endpoints are
exact by construction: at `T = 0` every smoothstep gate is 0 so `formed = 0`
and `gas(0) = 1`; at `AGE_REF` the ratio is 1 and `gas(AGE_REF) = gasFraction`.
Between, it is monotone (every smoothstep is monotone) and the histogram
approximation matches the exact O(N) sum within 0.25 % absolute (measured on
50 000 stars per type).

**The wiring.** `solveEpoch` reads `populations.viewGasNow` if present and uses
it for `gasRatio` / `armContrast`; the SFH `gasNow` stays for `gasRich` and the
downstream consumers. `main.js`'s `setEpoch` evaluates the view gas from the
renderer's histogram before calling `modelAtAge`; `redrawField` does the same
after the field draw builds the histogram. The `Evolve` preset's tick calls
`setEpoch` which now carries the view gas.

**Tests.** Four new checks in `galaxy-evolution-test.js` §10: histogram total
equals census count (every type); view gas exact at both endpoints; view gas
monotone decreasing; 1024-bin histogram within 0.25 % of the exact O(N) sum.
Measured errors are 0.02–0.06 % across all types at 50 000 stars — well inside
the budget.

**Validated.** `all-tests` **40/40**; `changed` **36/36**; `wgsl-exec`
**122/122**; `wgsl-validate` passes; `node --check` and `git diff --check`
clean. No browser/WebGPU visual verdict is claimed; V14 remains deferred.

## 0.7.3a — 2026-10-23 — The census is drawn in the reference frame (two 0.7.x corrections)

A review of 0.7.2/0.7.3 against what the browser would actually show found two
defects the CPU suite could not see, both in the renderer's wiring rather than
in the model. Neither is a new slice; both are corrections to the slices that
shipped, and the interface work they motivated is `ui.21` (the Formation
checks panel, `archive/ui.x-worklog.md`).

**Defect 1 — a deep-time draw baked its own degeneracy into the run.** The
field is drawn once and *placed* at every later epoch (E4), so the draw's
component mix is the census for the whole run. `sampleField` sampled that mix
from the model at the *running* epoch, and `writeProceduralRecords` measured
the epoch map against the same epoch (`orbit.setEpochBase(model)`). At `T = 0`
— where 0.7.2 sent the `Evolve` preset — that epoch is degenerate by
construction: `spheroid.a = 0`, and the disc height sits on `HEAT_FLOOR`, so
`deliveredMasses` integrates almost no disc and no bulge at all. Measured on
SBb at 20 000 stars: **thin 0.2 %, thick 0.1 %, bulge 0.0 %, halo 99.7 %**. The
run could never grow a disc, arms or a bar, because the census it carried had
none. The bug is invisible at 13.5 Gyr (reference ≡ draw) and mild at 0.2 Gyr
(the old start: 75/24/0.5) — it is exactly the deep-time start 0.7.2 added.

*Fix.* The census is drawn in the reference frame: `sampleField` samples
`galaxy.modelAtAge(model, AGE_REF)` (the same reference the birth law already
reads), stores it as `drawReference`, and `writeProceduralRecords` measures the
epoch map from it. Consequences, all intended:

- the component shares, truncation and birth windows are the present-day
  galaxy's at every draw, so a run started anywhere shows the same census;
- the epoch map is continuous by construction (the draw *is* the reference),
  and placing the reference draw back at `AGE_REF` is the identity map;
- the drawn vertical scale is the reference's instead of `H·HEAT_FLOOR²`, which
  also removes a 10⁶ heat ratio and its f32 precision risk;
- at `AGE_REF` the reference **is** the model, so every existing exactness pin
  (an AGE_REF model is bit-identical to the pre-0.6 one) holds untouched.

**Defect 2 — the 0.7.3 gas account never returned a value.** `buildBirthHistogram`
computed `birthHistPresenceRef = evaluatePresence(AGE_REF)` *before* setting
`birthHistValid = true`, and `evaluatePresence` returns 0 while the flag is
false. The reference sum therefore stayed 0, `censusGasAt` returned `undefined`
on every call, and `main.js` silently kept the SFH `gasNow` — the whole F4
feature, "shipped" in 0.7.3, was inert. The 0.7.3 tests missed it because they
re-implement the histogram locally instead of calling the page's account.

*Fix.* The flag is set once the bins are filled and before the reference sum is
evaluated; a zero reference sum clears it again. `censusGasAt` also returns the
two endpoints by name (`formed ≥ 1 → gasFraction`, `formed ≤ 0 → 1`): `1 − (1 −
f)` is not `f` in IEEE, and the arm contrast at the reference epoch must be
exactly 1, not 0.9999999999999999.

**The wiring.** One epoch solve is now the only writer: `main.js`'s
`solveEpochAt(age)` writes `viewGasNow` from the census, re-solves the model and
applies the epoch uniform. `setEpoch`, `redrawField`, `regenerateGalaxy` and the
boot after `renderer.prepare` all go through it, so a page that starts young
(`?age=`, the `Evolve` preset, a scenario) cannot keep the SFH prior while a
slider drag uses the account. `renderer.censusFormedAt(age)` exposes the formed
share beside the gas for the panel's readout.

**Tests.** `renderer-test` **145/145** (was 138): six new checks draw a second
renderer at `AGE_MIN` and pin the reference mix (every component share within
1e-3 of the reference draw), the epoch base being the reference (a > 0,
heat = 1), the identity map back at `AGE_REF`, the account's exact endpoints
(`formed(0) = 0`, `gas(0) = 1`, `formed(REF) = 1`, `gas(REF) === gasFraction`),
the arm contrast of exactly 1 through the account, and the monotone census. The
new `scenario` test (62 checks, now 70 with the live-line and picker checks
added in the ui.21 follow-up) pins the formation-checks table; `workspace` 54,
`panel` 16, `m1-smoke` 120 (the epoch check now follows the
`setEpoch → solveEpochAt` delegation and the panel wiring is pinned).

**Validated.** `all-tests` 41/41 in 208.7 s (the new `scenario` test included —
re-run in the foreground after a background run reported nothing), `changed`
14/14 in 16.0 s, `view-tests` 16/16, `world-tests` 16/16, `wgsl-exec` 122/122,
`wgsl-validate` passes, `node --check` and `git diff --check` clean. Still no
browser verdict: V14 is now pressable from the Formation checks panel
(`deferred-browser-visual-plan.md`).

## 0.7.3b — A preset's epoch is not a draw

*Follow-on from 0.7.3a, found while making the Formation checks panel usable.*

**The defect.** `applyPreset` re-sampled the field whenever the settings line
named an `age`, which is every Formation checks row and every `age=` URL. That
was the right rule while a draw's content depended on the epoch on the clock.
0.7.3a removed that dependence — `sampleField` now draws in the reference frame
(`drawReference = modelAtAge(model, AGE_REF)`) and the clock reaches the census
only through the epoch map — so the re-sample rebuilt an identical field and
charged for it: a full re-upload, `resetPatternPhase()`, `clearSelection()`, a
fresh trade-key check and the frame's only visible hitch. Pressing **Present
day** after **Gas-rich arms** is exactly this case, and it is the comparison the
panel exists to make: the press threw away the selection and restarted the
pattern to arrive at the same stars.

**The fix.** The cost rule is now data, in the module the tests read:

```js
Presets.applyPlan(settings, { budget, clusters })
  'rebuild'  type or seed named        → sample the field again
  'redraw'   budget/coefficient moved  → same galaxy, another draw
  'epoch'    age only                  → a re-solve and a uniform (E4)
  'none'     a look, a rate, a mode    → nothing that costs a draw
```

`applyPreset` branches on the plan instead of on which keys happen to be
present. `regenerateGalaxy` is untouched and still owns the rebuild (it is what
a `type=`/`seed=` preset and the boot path need); the epoch branch simply lands
`setEpoch(age)`, the same call the Age slider and the live clock already use
every frame, so the new path is the well-exercised one.

**What it costs.** Nothing was relaxed: the census solves through the same
`renderer.censusGasAt` → `viewGasNow` → `modelAtAge` chain, and the draw is
still reference-framed, so the stars a comparison lands on are the same bytes a
re-draw would have produced — measured again in `renderer-test` (145/145, the
exposure and census blocks unchanged). The difference is the work: no
`fieldSamples` increment, no pattern-phase reset, no selection clear.

**Validation.** `preset` 32/32 (the plan table for every combination, and every
scenario row resolving to `epoch`), `scenario` 70/70, `m1-smoke` 120, `panel`
16, `workspace` 54, `renderer` 145/145, `changed` 14/14 in 15.7 s. No browser
verdict is claimed: whether the press reads as instant is V14d's question, and
only a browser can answer it.
