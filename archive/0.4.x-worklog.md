## 0.4.1 — review fixes: group kinematics, CPU/GPU parity, family tagging

Review of the initial slice against the plan, driven by the visual bug report
"the bar is slower on orbits than stars near it" (and a list of latent parity
defects found while reproducing it):

**The reported bug and the fix (plan §1.1a, new).** The bar already rotated
rigidly at Ω_p, but every disc star *inside corotation* (R_CR = vFlat/Ω_p ≈ 5.5 kpc
on the MW preset) circulates at Ω(R) — up to 5.5× the pattern speed — so the bar
visually lagged the stars mixed into and around it. Fix: the **group zone** — the
disc family rotates at Ω_p inside R_CR (continuous there, since Ω(R) crosses Ω_p
exactly at the seam), differential outside; Ω_p = 0 types (S0, E, Irr) never lock.
Bar + arms + inner disc now turn as one group. Cost: one `select` — group speed is
the same closed form with a shared ω, so the §4 budget does not move. Bar-family
wobble was zeroed in the tables (rigid body; the 2:1 loop is a later refinement).

**Parity defects fixed (each would have shown as unreal motion):**

- The WGSL hard-coded the Milky Way's numbers (0.041 / 0.225 / 0.5 and its own
  pressure clock ×0.1 off) while the CPU mirror read `model.dynamics` — every
  non-MW type drew with MW rotation and labels diverged from stars. The uniform
  now carries `dynA`/`dynB` (8 floats packed by `orbit.packOrbitDynamics`;
  112 → 144 bytes; all defaults applied CPU-side so the shader hard-codes
  nothing — `wgsl-validate` enforces this).
- The shader reduced only the bulk θ before `sin` and reused it for the epicycle
  arguments — every wobble phase snapped once per revolution. Both sides now
  reduce the **full** argument (`sinTau`), keeping epicycles continuous across
  bulk wraps (orbit-test probes ±ε around a wrap).
- Wobble amplitudes disagreed 15× (CPU 0.12 vs GPU 0.008 kpc scale) and pressure
  had wobble on one side only. One law both sides: disc `A = rank·2σThin/κ(R)`
  with vertical 0.2× capped by `discHeight`; pressure `A = rank·pressureAmpScale`
  (virial `2σ/ω̄(1 kpc)`, bulge-capped at 0.3× semimajor axis, E uncapped),
  boiling at the spheroid clock `ω̄(r) = 0.05/max(r^1.5, 0.01)`.
- Landmarks were written with family bits 0 (= pattern) while labels/picking
  computed family from spectral class — G stars' labels drifted off their own
  stars at any non-zero rate. One rule now: `familyFromColorIndex` used by the
  record writer, `label-layer.js` and `selection.js`.
- The shipped catalog bundle predates families: `tile-loader.decodeCell` stamps
  them from the colour index on decode (idempotent, no payload re-encode).
- Object members got an explicit family (age < 100 Myr → pattern, globulars →
  their component's family) instead of accidentally landing on family 0.
- Nebula billboards never moved although the plan requires gas to follow the
  pattern: the nebula vertex shader now applies the same rigid θ = Ω_p·T about
  the model centre (documented deviation from the plan's CPU path — keeps the
  frame loop allocation-free).
- `patternLock` (plan §3.3 flag) is now honoured in `omegaFor`/`orbitOmega`.
- Dead `packOrbit`/`encodeOrbit` stubs replaced by `encodeJitter`; `OrbitLib`
  added to `export-parity-test`'s module table.
