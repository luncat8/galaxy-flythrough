# 0.3 — Galaxy Types, Stellar Objects & Galaxy Age

The engine today renders one galaxy: the hard-coded Milky Way in `src/math/density.js`
(thin/thick disc, triaxial bulge, power-law halo, two-armed spiral modulation) with the
stellar populations of `src/math/star-types.js` and the placement rules of
`src/math/nebula.js`. Everything downstream — sampling, the WGSL density mirror, nebula
placement, the local gap-fill — reads those constants. This plan parameterises the model
so the same pipeline flies through different galaxy types, gives those types proper
stellar objects (nebulae *with* the stars that belong to them), and finally adds galaxy
age as a population-synthesis knob.

Four releases, each shippable alone:

| Release | Theme | One line |
|---|---|---|
| 0.3.0 | Galaxy types | The `GalaxyModel` descriptor, type → parameter table, type selector UI. Four types prove every axis. |
| 0.3.1 | Different types, improved star distributions | The full Hubble zoo: E0–E7, S0, Sa–Sd, SBa–SBd, Irr. Barred forms, flocculent arms, metallicity gradients, clumpy irregulars. |
| 0.3.2 | Objects like nebulae with proper star distributions | Composite objects: HII region + OB association, open and globular clusters, planetary nebula + central star — each with its own internal density profile. |
| 0.3.3 | Galaxy age | Star-formation history per type; the population (colours, giants, white dwarfs, nebula abundance) follows the galaxy's age. |

Ground rules inherited unchanged: density field is the source of truth, truncation lives
in the model, stable hash (no PRNG state), no per-frame allocations, `file://` classic
scripts, WGSL as mirrorable parts. 0.4 (star movement) consumes the descriptor this plan
defines; see `0.4.0-plan.md`.

## 0.3.0 — Galaxy types (the framework)

### The GalaxyModel descriptor

One plain object, created once per galaxy, threaded through every consumer
(`density.js`, `sampling.js`, `star-types.js`, `nebula.js`, the WGSL mirrors):

```js
// src/math/galaxy.js (new)
GalaxyModel = {
	seed: 42,                    // master hash seed; same seed + params = same galaxy
	type: 'SBb',                 // canonical type string, see the table below
	T: 3,                        // de Vaucouleurs stage index (see below)
	barred: true,

	// Structural parameters. Exactly the fields density.js hard-codes today.
	thin:  { L, H, amp },
	thick: { L, H, amp },
	spheroid: { profile: 'sersic' | 'plummer', a, b, c, r0, n, amp, tiltDeg },   // bulge or E body
	halo:  { a_h, rMax, power, amp },
	arms:  { m, amp, pitchDeg, Rs, phase0, flocculence },   // amp 0 = smooth disc
	truncation: { discRadius, discHeight, spheroidRadius },

	// Population knobs consumed by star-types.js / nebula.js.
	populations: {
		gasFraction,      // 0 (quenched) .. 0.5 (gas rich); gates young stars + gas nebulae
		youngScaleHeight, // HII/OB vertical thickness (fraction of disc H)
		spheroidOld,      // bool — spheroid population is metal-poor old (always true in 0.3.0)
	},

	// Filled in by 0.4; present as a stub from 0.3.0 so the descriptor is stable.
	dynamics: { vFlat, coreRadius, omegaPattern, dispersions... },

	scaleKpc,                    // one overall size multiplier (see Scaling)
	homePosition, homeYawPitch,  // per-type camera start (see Modes and home)
}
```

`createGalaxy(options)` builds a model from `(type, seed, overrides)`. The Milky Way
preset is `type: 'SBbc'`-ish (barred, Sb/Sbc) with today's exact numbers preserved as
the default — the existing test suite must pass unchanged on the default model.

### Type → parameter table

The type string maps to `T` (de Vaucouleurs stage, −5…10) plus `barred`. 0.3.0 ships
**four types**, chosen so every parameter axis is exercised, not for coverage:

| Type | T | What it proves |
|---|---|---|
| `E4` | −2 | No disc, no arms, no gas — the spheroid-only path. |
| `S0` | 0 | Disc + spheroid, no arms, quenched — the "disc with armAmp 0" path. |
| `SBb` (Milky Way) | 3, barred | The default. Bar + arms + all four components. |
| `Sc` | 5 | Late-type: thin small spheroid, open arms (high pitch, low contrast spread over more arms), gas rich. |

0.3.1 replaces this quartet with the full table; the mapping below is the one it extends.

First-order parameter mapping (tuned so the *shapes* read correctly at fly-through
scale; ranges from Kennicutt 1981 pitch-angle sequence and the Roberts & Haynes 1994
type trends):

```
spheroid/disc mass ratio B/T:  E 1.0 → 0.4 over E0..E7 · S0 0.5 · Sa 0.3 · Sb 0.15 · Sc 0.05 · Sd 0.02
spheroid Sersic n:            E 4 (de Vaucouleurs) · early bulges 2 · late pseudobulges 1
disc H/L ratio:               S0 0.15 · Sa 0.12 · Sb 0.09 · Sc 0.07 · Sd 0.06   (early types puffier)
arm pitch (deg):              Sa 7 · Sb 10 · Sc 15 · Sd 22                        (Kennicutt 1981)
arm number m:                 2 (grand design) .. 4 (flocculent blend)
arm contrast amp:             S0 0 · Sa 0.15 · Sb 0.20 · Sc 0.25 · Sd 0.30
gasFraction:                  E 0 · S0 0.02 · Sa 0.08 · Sb 0.15 · Sc 0.30 · Sd 0.45 · Irr 0.5
```

Each structural parameter is a monotone function of `T`, interpolated through these
anchors by a flat data table in `galaxy.js` — no if-else chains (AGENTS.md style rule).
Amplitudes are renormalised after parameterisation so the disc still reads as `amp 1.0`
against the spheroid (the B/T ratio *is* the renormalisation).

### Scaling

Types differ in size as well as shape. Every length in the model is authored in model
units and multiplied by `scaleKpc` at construction:

```
E4:    scaleKpc 1.5   (R_e ≈ 1.5 kpc body — compact; spheroid semiaxes scale together)
S0:    scaleKpc 1.0   (disc L ≈ 2.5 kpc)
SBb:   scaleKpc 1.0   (L = 2.6 kpc — exactly today's Milky Way)
Sc:    scaleKpc 1.4   (L ≈ 3.5 kpc, puffier arms)
```

`GALACTIC_R0` and `GALACTIC_CENTRE` become properties of the model (sun frame only
exists for the Milky Way preset — see below). `density.js` stops exporting module-level
constants and takes `(model, x, y, z)`. The one-argument call sites all already funnel
through `rhoTotal`/`rhoDecomposed`, so the blast radius is contained.

### The spheroid profile

`plummer` stays (it is what the bulge is today and what the sampling inverter knows).
`sersic` is added for E/S0 bodies:

```
rho(R_e) ∝ exp( −b_n · ((R_e / r_e)^(1/n) − 1) ),   b_n ≈ 2n − 1/3
```

Sampled like the bulge: radial inverse-CDF by bisection (the same trick
`sampleDiscRadius` uses — 32 deterministic steps), isotropic directions, triaxial axis
scaling. Truncated at `spheroidRadius` effective radii (`TRUNCATION.bulgeRadius`
generalised); the truncation lives in the model exactly as AGENTS.md requires.

### Density is parameterised; the WGSL mirror follows

This is the one architectural consequence that must not be deferred. `SHADER_PARTS
['density']` currently re-types the constants so `wgsl-validate.js` can diff the WGSL
against `src/math/density.js`. With a parameterised model the constants cannot be in
the source text any more. Change the mirror contract:

- The WGSL part carries a `DENSITY_PARAMS` uniform struct (component scales, spheroid
  axes + profile selector, halo power, arm parameters, truncation values) and the
  *formulas* only.
- `wgsl-validate.js` diffs the formulas as today and additionally checks the struct
  field list and order against the JS packer (string list comparison — same technique
  as the binding checks already in place).
- `star-sprites.js` packs the struct from the model at build / regenerate time. One
  upload, not per frame.

The compute paths (`procedural-gen`, `cull`) read the same uniform. Nothing else in the
shader stack changes.

### Mode rule: catalog and landmarks are Milky Way only

The Gaia subset, `landmarks.js` and `constellations.js` describe real stars in the real
Milky Way. They are meaningless in an E4. Rule, enforced in `main.js`:

```
type is the Milky Way preset  →  Hybrid mode (catalog + procedural + landmarks), today's behaviour
any other type               →  Game mode (pure procedural); catalog streaming off,
                                landmarks/constellations/labels hidden
```

The sun-centred coordinate frame (`GALACTIC_CENTRE` at +X) is a Milky Way preset
property. Other types use galactocentric coordinates with the origin at the centre; the
home position is placed out at a viewing radius instead:

```
Milky Way:  START_POSITION (0, 0, 0.005), looking at the core — unchanged
disc types: (0, −3.5·L, 0.5·L) kpc in model units, looking at the centre: the classic
            three-quarter disc view
E types:    (0, −4·R_e, 1.2·R_e), looking at the centre
```

### UI

The settings menu (Tab) grows a **galaxy** section above the HDR section:

```
type       [⟨ E4 / S0 / SBb / Sc ⟩]     — stepped select
seed       [ 42 ]  [ 🎲 ]  [ new ]       — number field, randomise, apply
```

Changing type or seed marks the model dirty; `new` (or Enter) regenerates: rebuild the
procedural field, rebuild gap-fill, switch mode if needed, reset the camera to the type
home. Regeneration is synchronous, same as the startup field build today (~0.7 s at
300k) — acceptable for a deliberate action; a progress state is out of scope.

Keyboard: `G` cycles the four types (one-shot, ignores `e.repeat`). The overlay shows
`galaxy SBb #42` next to the drawn-stars line.

## 0.3.1 — Different types & improved star distributions

### The full zoo

`galaxy.js` grows the complete anchor table. Type codes: `E0…E7`, `S0`, `Sa…Sd`,
`SB0…SBd`, `Irr` (≈ T = 9–10), selectable in the UI (the stepped select becomes a
`<select>` with 20 entries; `G` cycles a shortlist of five: E4, S0, SBb, Sc, Irr).

New shape machinery, one sampler per family (all rejection-free, all deterministic):

1. **Sérsic spheroids** (already in 0.3.0) — E0–E7 vary axis ratio and `n` (4 for
   giants, down to 2 for faint E7/S0). E flattening: `c/a` 1.0 → 0.5 along E0…E7.
2. **Barred spheroids** — `SB*`: the spheroid grows a bar: replace the triaxial bulge
   with `bar: { length, width, thickness, boxiness, tiltDeg }`. Density is a
   superposition of a boxy/peanut inner part and exponential end caps (the
   boxy/peanut profile of the Milky Way bar, Portail 2016 already cited in plan.md §4);
   the sampler draws a bar-aligned uniform in the boxy volume with the exponential
   cap rejection replaced by an inverse-CDF along the bar major axis. Arm `phase0`
   snaps to the bar ends (arms start where the bar ends) — that is what makes SBb read
   as *barred* rather than "Sb with a stick".
3. **Flocculent arms** — `arms.flocculence ∈ [0, 1]` blends the smooth `cos(m·φ − …)`
   modulation (grand design, today) with a log-spiral FBM noise field (three octaves,
   hash-based value noise in (ln R, φ) space). Sc/Sd default flocculent ≈ 0.5, Sa/Sb
   grand design ≈ 0.1. `armFactor` becomes a two-term product; `distanceToNearestArm`
   keeps the grand-design ridge line and is used only for young-pop placement (the
   noise term biases, it does not move, the ridge).
4. **Irregulars** — no arms, no symmetry: `rho = rho_base · exp(k_fbm · FBM(x, y, z))`
   with 10–20 hash-placed hotspots (star-forming clumps, radius ~ 0.3 kpc, density
   boost ×3) and a mild global rotation (added in 0.4 via `dynamics.vFlat ≈ 50 km/s`).
   The sampler becomes two-stage: draw from the smooth base (disc-like, large H/L),
   then apply clump assignment by hash (a star near a hotspot is pulled toward it by a
   fixed factor) — cheap, stable, and the density test measures the resulting field
   against the same rule.

### Improved star distributions

What "improved" means concretely, beyond the type shapes above:

- **Population gradients.** `star-types.js` already ages stars by component and arm
  distance. Add radial metallicity, as a *colour* modifier only (no new physics):
  thin-disc stars dim/redden toward the edge (`Δ colourIndex` up to +1 step at
  `2·L`), spheroid stars metal-poor from birth (bluer turnoff + redder giants —
  approximated by shifting 20% of spheroid giants one LUT step redder). Gradients are
  per-type: flat in E, steep in Sc.
- **Arm-hugging young population.** O/B placement tightens from "near an arm" to a
  proper ridge distribution: `distToArm` becomes a half-normal with σ = arm width
  (width from `arms.amp` and pitch), so young stars form spurs and clumps along the
  arms instead of a uniform inner tube. OB *clustering* lands in 0.3.2 as objects; this
  item is the smooth version.
- **Vertical structure.** Disc flaring: scale height grows with R (`H(R) = H0·(1 + flare
  · R/L)`), thin and thick separately. E/S0 spheroids keep the anisotropic flattening
  from the type table.
- **Radial profile edge cases.** Late types get a central hole or flat core option
  (`disc.coreRadius`, used by Sd/Irr — real Sd galaxies show it); early types keep the
  cusp. Sampling inverter gains the core radius term (closed-form — the exponential
  inverse just starts at `coreRadius`).
- **Density parity everywhere.** Every new profile gets the sampler ↔ density parity
  treatment in `density-distribution-test.js` (run per type). The truncation rule is
  unchanged and applies per component: nothing is sampled where the field reads zero,
  and every derived placement (nebulae, objects, gap-fill) reads the same field.

### Tests (0.3.1)

- `galaxy-types-test.js` extends to the full table: monotone trends across T for B/T,
  pitch, gasFraction, H/L; bar geometry sane (length < disc radius, arms attach at the
  ends within tolerance); flocculence monotone in T for the Sc–Sd sequence.
- `density-distribution-test.js` runs the parity suite for {E4, S0, SBb, Sc, Irr}
  (component shares within 2% of the analytic masses; radial and vertical histograms
  within tolerance).
- `star-types-evolution-test.js`: metallicity-gradient checks (mean colour index rises
  with R in discs, flat in E), young fraction tracks `gasFraction` and arm proximity.

## 0.3.2 — Objects like nebulae, with proper star distributions

`nebula.js` places loose nebulae from `pGas`/`pStellar` today. Real nebulae are not
loose: an HII region *is* its OB association, a reflection nebula sits on its B stars,
a globular cluster is a stellar system that happens to be spectacular. 0.3.2 turns
placement into **composite objects**, each with an internal star distribution.

### Object catalogue

| Object | Gas | Members | Internal distribution | Population |
|---|---|---|---|---|
| HII region / OB association | HII or reflection nebula billboard | 20–200 | Fractal (fbm-cored, effective radius ~ 50–150 pc) | `gasFraction`-gated young: O/B + A/F, ages 1–20 Myr |
| Open cluster | none (or residual reflection) | 30–300 | Plummer, r_c ~ 1 pc, tidally cut at 10–30 pc | thin-disc mix, ages 10 Myr–1 Gyr |
| Globular cluster | none | 200–2000 | King profile (W0 ≈ 6), r_c ~ 1–3 pc | metal-poor old: RG + WD + low-mass, no O/B |
| Planetary nebula | planetary (green [OIII]) billboard | 1 central star + 0 | point | post-AGB central star + ionised shell |
| SNR | shell billboard | 0 | — | — |

### Placement

`placeObjects(seed, N, box, model)` generalises `placeNebulae` — same candidate scheme
(sample from the field, accept by probability). Probabilities extend the existing two
terms:

```
pHII        = f(gasFraction) · inDisc(z < youngScaleHeight) · armBoost · ageGate     // 0.3.3 adds ageGate
pOpen       = inDisc · gasFraction-weighted
pGlobular   = f(spheroid mass) · r_e-biased (radial concentration ∝ spheroid density)
pPlanetary  = pStellar (bulge/thick disc, unchanged)
pSNR        = pStellar · thinDiscTracer (massive-star remnants — arms + disc)
```

Each accepted object hashes `(seed, index)` → type roll, size, richness, internal
seeds. Everything stays a pure function of the hash — the AGENTS.md stability rule
applies to members: member *i* of object *j* is `(seed, j, i)` through the same
component/IMF pipeline as field stars (`sampling.js` + `star-types.js` with the
object's age override).

### Proper member distributions

Members are generated by inverting the object profile — no rejection:

- Plummer: `r = a·u^(1/3)·(1−u)^(−1/3)` closed form (standard), uniform direction.
- King W0=6: numeric inverse-CDF by the same 32-step bisection sampler pattern.
- Fractal OB: three-octave value noise in object-local space, stars drawn where
  `noise > τ`, which is a fixed acceptance curve measured once and inverted by
  bisection in the experiment.

Mass segregation (optional polish): member masses biased low → larger radii (rank
correlation between the mass roll and the radius roll), a one-line sort of the hash
rolls. It reads as "real cluster" at close range and costs nothing.

### Rendering and budget

- Members are ordinary `StarPacked` records in a new fixed **objects block** of the
  star buffer: `[global][landmarks][local gap-fill][objects][catalog]`. Written on
  regenerate, not per rebuild. Budget: `OBJECT_MEMBERS_DEFAULT = 20000` (320 KB) —
  same order as the gap-fill block; drawn always (they are point stars).
- Nebula gas renders as billboards (plan.md §10 tier 1) in their own additive pass
  after the sprites: camera-facing quads, size from `size`, colour from
  `NEBULA_COLORS`, soft radial alpha (a tiny fragment falloff, no texture files).
  Cull by screen-size (skip below ~4 px) and distance (beyond 5 kpc a nebula is a
  smear — drop it). Shell/volumetric tiers stay in plan.md §10 / Milestone 6; 0.3.2
  ships billboards only, which is what "objects like nebula" needs.
- The 2D label layer can name the top objects (HII region, cluster) — optional.

The sun-relative Hybrid mode gets object placement too (the real Orion nebula is a
landmark; procedural HII regions around it are allowed — the thin disc there is the
same field).

### Tests (0.3.2)

- `experiments/object-placement-test.js` (new): object density follows `pHII`/etc.
  (measured by R, |z|, arm distance buckets — the `nebula-placement-test` harness);
  member histograms match Plummer/King/fractal within tolerance; member stability
  (same seed ⇒ same members); type shares vs `gasFraction` (E: zero HII/open; Sc:
  most).
- `nebula-placement-test.js` keeps passing for the loose-probability layer (it now
  runs over `placeObjects` with object types flattened to gas types).
- `renderer-test.js`: objects block layout + instance counts; billboard pass is drawn,
  culled below the size floor.
- Budgets asserted: `sum(members) ≤ OBJECT_MEMBERS_DEFAULT` always.

## 0.3.3 — Galaxy age

The final parameter: `age` in Gyr (0.2 – 13.5, menu slider). Age does not animate the
galaxy (0.4 moves stars; nothing *evolves* them over scrub time in 0.3) — age is the
**generation parameter**: at what cosmic epoch this galaxy is frozen.

### Star-formation history per type

Formation-time sampling: `t_f ∈ [0, age]`, drawn from `SFR(t) ∝ exp(−t/τ)` (delayed
exponential `t·exp(−t/τ)` is the better fit — use it):

```
τ (Gyr):     E 0.4 (monolithic burst then dead) · S0 1.0 · Sa 3 · Sb 5 · Sc 8 · Sd 12 · Irr 15 (≈ constant)
quenching:   E and S0 additionally clamp t_f < tq = 1.5·τ  (star formation stops)
gas depletion: gasFraction_effective = gasFraction · exp(−age / (2·τ))  — feeds 0.3.2's
               pHII and the young population: old Sc is dimmer in HII than young Sc,
               an old E has nothing.
```

Everything else reuses what `star-types.js` already does with age: IMF mass → main
sequence lifetime → O/B gone after ~40 Myr–0.4 Gyr, AGB giants peaking at intermediate
ages, white dwarfs accumulating with age. The change is *where the ages come from*:
today they are drawn from local component priors (arms young, halo old); 0.3.3 scales
those priors by the galaxy's own clock — `ageLocal = u · min(age, componentAgeScale)`,
so at `age = 1 Gyr` even the halo is young (blue, few WDs) and at `age = 12 Gyr` the
thin disc is middle-aged with a full WD/RGB mix.

### Visual consequences (what the slider must visibly do)

| | young (0.5–2 Gyr) | old (10–13.5 Gyr) |
|---|---|---|
| disc colour | blue-white, many O/B | yellow-red, O/B only on the freshest arms |
| giants | few | RGB bump visible as orange sparkle |
| white dwarfs | none | percolating faint blue points |
| gas nebulae | abundant, bright HII | rare (exp(−age/2τ) fade), mostly planetary + SNR |
| E galaxy | only if young (blue E — rare but real) | red spheroid, dead |

These are exactly the knobs `deriveStar` already computes from a per-star age — the
implementation is the age *distribution* and the `gasFraction` fade, plus a LUT
renormalisation so the mean luminosity of the field stays in the tuned exposure window
(age changes the mix; it must not change the overall exposure defaults).

### UI

```
age        [ ⟨————●————⟩  8.0 Gyr ]     — slider 0.2–13.5, live regenerate
```

Live regenerate is affordable: changing age re-rolls star properties only (positions
are age-independent in 0.3) — the same position samples, new masses/ages through the
hash, rewritten blocks. < 0.2 s at 300k. Overlay shows `age 8.0 Gyr`.

### Tests (0.3.3)

- `galaxy-age-test.js` (new): sampled `t_f` histograms match the delayed-exponential
  within tolerance for every type; `age = 1 Gyr` cuts O/B fraction to < 1% (versus
  > 5% at 12 Gyr Sc); WD fraction rises monotonically with age; nebula counts fall
  with age at fixed type; quenched types never draw `t_f` past `tq`; mean colour index
  rises with age (blue → red trend measured on the LUT weights).
- `star-types-evolution-test.js` gains the age-distribution mode (component priors ×
  galaxy clock) and keeps its current checks on the default model.

## Implementation order

1. **0.3.0a** `src/math/galaxy.js`: descriptor + anchor table + Milky Way preset that
   reproduces today's constants bit-for-bit; `density.js` takes the model;
   `DENSITY_PARAMS` uniform + `wgsl-validate` struct parity.
2. **0.3.0b** `E4`/`S0`/`Sc` shapes (sersic inverter, arm pitch/amp through the table,
   gas gating in star-types/nebula), mode rule, home positions, UI section, `G` key.
3. **0.3.1a** barred spheroid + arm phase0 coupling; flocculent arms; irregular FBM +
   hotspots.
4. **0.3.1b** population gradients, arm-ridge young placement, flaring, disc cores;
   per-type parity suite.
5. **0.3.2a** `placeObjects` + internal profile inverters + objects block in the star
   buffer (no gas rendering yet — objects as star concentrations already look right).
6. **0.3.2b** nebula billboard pass + size cull + budgets.
7. **0.3.3** SFH sampling, gas depletion, age slider with property-only regenerate,
   exposure renormalisation.

Steps 1–2 ship 0.3.0; 3–4 ship 0.3.1; 5–6 ship 0.3.2; 7 ships 0.3.3. Tests land with
each step, per the AGENTS.md workflow.

## Out of scope

- Isochrone-level stellar physics (real SPS tracks, dust radiative transfer). The
  population model stays "IMF + lifetime + LUT", just with honest age distributions.
- Evolution *over* scrub time: moving the age slider is a regenerate, not a
  time-lapse of stellar evolution. Combining age with 0.4's star time (stars ageing as
  T advances, births along arms) is a possible 0.5, deliberately not here.
- Mergers, tidal tails, satellite galaxies, cD envelopes.
- Textured / volumetric nebulae (plan.md §10 tiers 2–3 remain the target for hero
  objects).
- Per-type music or marketing names for the galaxies ("Andromeda-ish" etc.). Type
  codes only.
